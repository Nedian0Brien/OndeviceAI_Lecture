# 손마디 천지인 입력기

손 카메라 영상으로 한글 천지인 입력을 하는 프로젝트입니다. MediaPipe Hand Landmarker로 손 landmark를 추적하고, 입력 결과를 카메라 영상 위 HUD로 표시하며 `S`로 UTF-8 텍스트 파일에 저장합니다. 다른 프로그램에 키 입력을 전달하는 OS 입력기는 포함하지 않습니다.

현재 주 버전은 **손끝 꼬집기 입력기(`project01.py`)** 입니다. 엄지로 손끝을 꼬집으면 그 손가락이 버튼이고, 같은 손가락을 꼬집은 횟수로 그룹 안의 자모를 고릅니다. 목표 용도가 패스스루 VR이라, 카메라는 **눈 위치에서 손을 내려다보는 1인칭 배치**를 기준으로 합니다(기본값: 좌우 반전 없음). 설계 근거는 `.intent/*_pinch-cheonjiin.md`에 있습니다. 앞서 시도한 방식은 [이전 시도](#이전-시도)에 정리했습니다.

## 손끝 꼬집기 입력기 (`project01.py`)

### 자판

손 방향(손바닥 또는 손등이 카메라를 향함)마다 다른 키가 놓입니다. 손바닥 자세는 손등을 책상이나 무릎에 대고 손바닥을 위로 두면 편합니다.

| | 검지 | 중지 | 약지 | 소지 |
| --- | --- | --- | --- | --- |
| 왼손 손바닥 | ㅂ→ㅍ→ㅃ | ㄹ | ㅅ→ㅎ→ㅆ | ㅈ→ㅊ→ㅉ |
| 오른손 손바닥 | ㄱ→ㅋ→ㄲ | ㄴ | ㄷ→ㅌ→ㄸ | ㅇ→ㅁ |
| **왼손 손등** | **모음**: 꼬집기 ㆍ · 가로 끌기 ㅡ · 세로 끌기 ㅣ | 공백 | 확정 | . → , → ? → ! → 줄바꿈 |
| **오른손 손등** | 확정/공백 | - | - | - |

2026-10-23 자판을 두 번 바꿨습니다. 예전에는 모음 세 개가 왼손 세 손가락이었고, ㅂ·ㅅ·ㅈ 그룹과 문장부호는 오른손 손등 검지 쉬프트 뒤에 있었습니다. 그다음 모음 한 버튼을 왼손 손바닥 중지에 두었다가, 왼손 손바닥을 모두 자음으로 쓰려고 모음을 왼손 손등 검지로 옮기고 ㄴㄹ을 ㄴ·ㄹ로 나눴습니다. 손등 검지에 있던 지움 키는 없앴습니다(주먹으로 지웁니다).

### 규칙
- 같은 손·손가락을 다시 꼬집으면 순환합니다. **다른 키를 꼬집으면 앞 글자는 자동으로 확정**됩니다. 모음은 꼬집는 즉시 들어갑니다.
- **ㄴ·ㄹ**: 글자가 하나라 순환하지 않고 꼬집는 즉시 들어갑니다. `안녕`의 ㄴ→ㄴ은 확정 없이 오른손 중지를 두 번 꼬집으면 됩니다.
- **모음(왼손 손등 검지)**: 왼손을 뒤집고, 꼬집고 그대로 떼면 ㆍ, 꼬집은 채 손을 가로로 끌면 ㅡ, 세로로 끌면 ㅣ입니다(천지인 획). 꼬집는 동안 꼬집은 지점(엄지 끝과 검지 끝의 가운데)이 손 크기(손목~중지 뿌리)의 0.25배(약 2.3cm) 넘게 움직이면 끈 것으로 보고, 가로·세로 중 많이 움직인 쪽을 고릅니다. 떼며 엄지만 벌어지는 움직임은 세지 않습니다. 누르고 유지(실험)에서는 끌기가 ㆍ로만 들어갑니다.
  꼬집는 동안 화면에 꼬집은 지점이 지나온 길(선), 시작점 둘레의 끌기 기준 원, 지금 떼면 들어갈 획(ㆍ / ㅡ / ㅣ)이 뜹니다. 기준 원을 벗어나면 선과 획 표시가 초록으로 바뀝니다. 판정에 쓰는 프레임과 같은 점들입니다(`PinchTyper.drag_view`).
- **오른손 손등 검지**: 후보가 있으면 확정, 없으면 공백(손끝 라벨이 "확정"/"공백"으로 바뀝니다). `까까`의 ㄲ→ㄲ처럼 같은 손가락 그룹 자음이 이어질 때 확정이 필요합니다.
  - 손등에서 네 손가락을 모두 키로 쓰는 방식도 시험했지만, 손등이 카메라를 향하면 꼬집는 손끝이 카메라 반대쪽으로 굽고 엄지가 가려져 입력되지 않았습니다(2026-10-23). 그래서 오른손 손등에서는 검지만 받습니다.
- **왼손 손등 공백·확정·문장부호**: 왼손을 뒤집고 꼬집습니다.
- 손을 뒤집는 도중의 꼬집기는 입력하지 않습니다(꼬집기 시작과 뗄 때 방향이 다르거나, 처음·마지막 몇 프레임의 손 방향이 그 방향이 아닐 때).
- 손바닥 자판에서 소지 쪽이 카메라에 가깝게 25° 넘게 기울면 손 아래에 "엄지 쪽을 카메라로 돌려 주세요"가 뜨고, 그 자세의 꼬집기는 입력하지 않습니다. 카메라는 손 바로 위나 엄지 쪽에 둡니다.
- **주먹(양손)**: 지움. 마지막 자모 하나를 통째로 지웁니다(감 → 가 → ㄱ). 순환한 자음(ㅇ→ㅁ)은 ㅁ이 지워지고 ㅇ으로 되돌아가지 않습니다. **쥐고 있으면 0.5초마다 하나씩 계속 지웁니다.**
- 꼬집기는 손끝을 **뗄 때** 1회로 셉니다. 눌린 손끝 라벨에는 떼기 진행 호가 그려지고, 다 차면 입력됩니다. 주먹을 쥐는 도중 엄지가 손끝을 스치는 것은 입력하지 않습니다.
- 카메라 앱과 Vision Pro 앱은 같은 판정값을 씁니다(2026-10-24, 시연 카메라를 Vision Pro와 비슷한 위치·시야각으로 둠). 손을 뒤집은 직후 꼬집기를 쉬는 규칙(0.3초)은 기본으로 끕니다(뒤집고 바로 친 모음이 씹혔음). 주먹을 연달아 쥘 때는 손을 반쯤만 펴도 버튼이 다시 펼쳐지면(주먹이 아닌 상태 0.15초) 다음 주먹으로 지웁니다.
- 실험: `--hold 0.3`이면 꼬집고 0.3초 머물러야 입력합니다(누르고 유지). 2026-10-23 사용해 본 결과 엄지가 쉬거나 돌아오는 자리에 머문 것도 입력되어 기본으로 쓰지 않습니다.
- 각 손가락 끝 바로 바깥에 **다음에 꼬집으면 입력될 글자**가 표시됩니다(`T`로 끄기). 버튼 둘레 눈금이 다가온 정도만큼 흰색으로, 누르는 동안에는 떼기 진행만큼 파랑으로 켜집니다.
- 손바닥 가운데 원: 손가락 방향마다 다가올수록 길어지는 파랑 막대, 누르는(가장 많이 다가온) 손가락을 가리키는 삼각형, 주먹 지움 진행만큼 빨갛게 켜지는 바깥 막대 링, 가운데 "주먹 쥐기로 지움". 화면은 가는 선·눈금·파랑 강조로 그립니다(`common/hud.py` 선 HUD 색과 같은 값을 Vision Pro 앱이 씁니다).
- 자음 그룹처럼 순환하는 키는 나머지 글자가 손가락을 따라 손바닥 마디 쪽에서 기다립니다(예: 검지 손끝 ㄱ, 가운데 ㅋ, 손바닥 마디 ㄲ). 꼬집어서 순환하면 다음 글자가 손끝으로 올라오고, 방금 입력된 글자는 손바닥 마디로 돌아갑니다.

예: `안녕` = ㅇ(오른 소지) · 왼손을 뒤집어 모음 ㅣ(세로 끌기) ㆍ · ㄴ(오른 중지) · ㄴ · 모음 ㆍ ㆍ ㅣ(세로 끌기) · ㅇ

마우스 모드(오른손 손등 커서, 클릭, 화면 버튼, `--os-mouse`)는 2026-10-23 뺐습니다. 오른손 손등 검지는 확정/공백입니다. 저장·일시정지·도움말·복사·전체 지우기는 키보드 단축키로 합니다.

### 실행

```bash
python Project01/project01.py --camera 0                 # 1인칭 카메라 (iPhone 연결 시 0번)
python Project01/project01.py --camera 0 --log Project01/data/pinch-log.jsonl   # 손 신호·landmark 기록(판정값 조정용)
python Project01/project01.py --camera 0 --collect      # 기록 모드: 안내한 손가락을 꼬집어 정답이 붙은 기록을 남김
python Project01/project01.py --mirror                   # 카메라가 사람을 마주 보는 셀카 배치
python Project01/project01.py --camera 0 --resolution 1920x1080   # 카메라 해상도 직접 지정
python Project01/project01.py --pipeline usb             # Jetson USB 카메라 (GStreamer 640x480 30fps)
python Project01/project01.py --demo                     # 카메라 없이 '안녕하세요' 재생
```

| 키 | 기능 |
| --- | --- |
| `1`~`4` / `7` `8` `9` `0` | 왼손 / 오른손 검지~소지 꼬집기 시험 (Shift와 함께 누르면 손등: `!` 모음 ㆍ, `@#$` 공백·확정·문장부호, `&` 확정/공백. `-` 모음 가로 끌기 ㅡ, `/` 모음 세로 끌기 ㅣ) |
| Space / Backspace | 왼손 / 오른손 주먹(지움) 시험 |
| `[` / `]` | 꼬집기 판정값 낮춤 / 높임 (잘 안 잡히면 `]`, 닿기 전에 입력되면 `[`) |
| T / K / D | 손끝 라벨 / 화면 아래 자판 지도 / 손가락별 진단 수치 켜기·끄기 |
| S / P / H | 저장(`Project01/pinch_output.txt`) / 일시정지 / 도움말 |
| C / X | 입력한 글 복사 / 전체 지우기 |
| G | 진단 스크린샷 저장 (`Project01/data/snapshots/`, 1초마다 자동 저장) |
| F | 전체 화면 켜기·끄기 |
| Q / Esc | 종료 |

### 해상도

- 시연 장비인 Jetson USB 카메라(GStreamer 640×480 30fps)를 기준으로 합니다.
- `--resolution` 기본값 `auto`는 macOS에서 1280×720, 그 밖의 환경(Jetson)에서 640×480을 요청합니다. `--pipeline`을 쓰면 파이프라인 문자열의 해상도를 따릅니다.
- 손 검출에는 가로 640px 이하로 줄인 영상을 넣고(`--detect-width`), 화면은 원래 해상도로 그립니다. landmark는 0~1 비율 좌표라 그대로 쓸 수 있습니다. 그래서 화면 해상도와 상관없이 검출 조건이 Jetson 시연과 같습니다.
- 시작할 때 실제로 들어온 카메라 해상도와 검출 입력 크기를 터미널에 출력합니다. 창은 영상 크기에 맞춰 엽니다(가로 960~1440). `F`로 전체 화면을 켭니다.
- 이 Mac에서 측정한 프레임당 처리 시간(검출 + 신호 + HUD, 같은 부하 조건)은 다음과 같습니다.
  - 640×480: 10.1ms → 8.3ms
  - 1280×720: 16.8ms → 12.2ms
  - 1920×1080: 30.0ms → 22.6ms
  - 줄어든 이유는 두 가지입니다. 유리 재질 흐림을 버튼이 있는 영역에만 적용했고, 손 검출에 넣는 영상을 줄였습니다.

### 판정 방식
- 꼬집기 거리 = 엄지 끝~손가락 끝마디 선분(DIP→TIP) world 거리 / 손목~중지 뿌리 길이. landmark가 뼈 축 위에 있어 살이 맞닿아도 0이 되지 않으므로, 손끝 점이 아니라 끝마디 선분까지 잽니다. `D`를 누르면 손가락별 값이 보입니다.
- 어느 손가락인지는 **직전 값보다 얼마나 다가왔는지**로 정합니다(`pinch_typer.FingerPinch`).
  - 손가락마다 최근 0.5초의 최대값을 기준값으로 둡니다. 기준값보다 0.15 이상 다가왔고 0.30 아래인 손가락만 후보입니다.
  - 후보 중 가장 가까운 손가락이 다른 손가락보다 0.03 이상 가까우면 접촉을 시작합니다(중지를 꼬집으면 약지도 함께 가까워지기 때문).
  - 접촉 중 다른 후보가 0.03 이상 더 가까워지면 그 손가락으로 옮깁니다. 엄지가 약지로 가는 길에 검지 옆을 먼저 지나가도 약지가 됩니다.
  - 고른 손가락이 얕게(최저값 0.20 위) 다가왔다가 벌어지는데, 아직 0.30 안에 있고 0.03 이상 더 가까운 손가락이 있으면 떼지 않고 그 손가락으로 옮깁니다(중지로 가는 길에 검지를 스친 경우, 2026-10-23 기록).
  - 누르고 유지(실험, `--hold`): 고른 손가락이 0.20(손바닥 검지 0.10) 아래에 0.3초 머물면 1회 입력합니다(0.25 위로 벌어지면 다시 잽니다). 거리만으로는 스침과 꼬집기가 갈리지 않아(정답 기록의 꼬집기 102개와 자유 입력에서 바로 지운 스침 14개의 최저 거리 중앙값 0.08 / 0.07, 접촉 길이 0.23 / 0.27초) 머문 시간으로 의도를 봅니다. 스침 14개 중 0.20 아래에 0.3초 넘게 머문 것은 2개였습니다.
  - 뗄 때 입력(기본): 고른 손가락이 접촉 중 최저값보다 0.12 이상(0.38 위면 항상) 2프레임 연속 벌어지면 1회 입력합니다. 한 프레임만 튀는 것은 세지 않습니다. 0.08로 낮춰 본 적이 있으나(눌린 채로 덜 벌리고 다시 꼬집는 경우) 스침이 더 잘 입력되어 0.12로 되돌렸습니다(2026-10-23).
  - 방금 뗀 손가락은 1초 안에 0.08만 다가와도 다시 꼬집은 것으로 봅니다(처음 꼬집기는 0.15). 덜 벌린 상태에서 다시 꼬집기 때문입니다.
  - 고른 손가락을 떼는 중에는 다른 손가락으로 옮기지 않습니다. 떼며 엄지가 옆 손가락으로 미끄러진 것을 그 손가락의 꼬집기로 바꾸지 않기 위해서입니다.
  - 오른손 검지 지나감: 엄지가 쉬는 자리가 검지 옆이라, 다른 손가락으로 가거나 돌아올 때 검지를 실제로 지나갑니다(영상 확인). 오른손 손바닥 검지 입력은 다른 손가락 입력을 뗀 뒤 0.25초 안에 시작했거나, 접촉 동안 검지가 5° 넘게 굽지 않았으면 버립니다. 2026-10-23 자유 입력 기록에서 지움이 따라온 검지 오입력이 9 → 5개로 줄었고, 정답 기록의 실제 검지 꼬집기는 줄지 않았습니다. 왼손에는 적용하지 않습니다.
  - 0.10초보다 짧은 접촉은 엄지가 손끝을 스친 것으로 보고 버립니다(정답 기록의 실제 꼬집기는 모두 0.13초 이상).
  - 검지 겹침: 엄지가 검지 옆에서 쉬다가 중지·약지를 꼬집으면 엄지 옆면이 검지를 눌러 검지 값도 함께 내려옵니다. 검지로 판정된 접촉에서 다른 손가락의 최저값이 검지 최저값 +0.05 안에 있고, 그 손가락이 접촉 동안 검지보다 10° 이상 더 굽었으면(MCP·PIP·DIP 굽힘 합, `common.pose.finger_flex`) 그 손가락으로 바꿉니다. 정답이 있는 접촉 90개에서 78 → 83개 맞음, 실제 검지 꼬집기는 바뀌지 않았습니다.
  - 엄지 가림: 손의 긴 축 기준 기울기(`common.pose.palm_roll`, 이미지 landmark의 상대 깊이 z로 계산)가 접촉 동안 -25° 이하이면(소지 쪽이 카메라에 가까움) 손바닥 꼬집기를 버립니다. 이 자세에서는 엄지와 맞닿는 곳이 가려져 MediaPipe가 엄지를 검지 옆으로 추정합니다. 2026-10-23 기록에서 -28° 이하 차례 8개 중 7개가 검지(ㄱ·ㅣ)로 잘못 입력되거나 입력되지 않았고, 꼬집은 손가락 값은 0.44~0.70에서 내려오지 않았습니다. 엄지 쪽이 가까운 기울기(+32°까지)는 모두 맞았습니다.
  - 절대 거리만 쓰지 않는 이유: 정답이 붙은 기록(2026-10-22)에서 쉬는 자세의 검지가 0.11~0.28로, 실제로 꼬집은 소지(0.17~0.23)만큼 가까웠습니다. 원래 가까운 손가락은 다가오지 않으므로 후보가 되지 않습니다.
- 판정값은 모든 사람에게 같은 고정값이며 사용자별 보정 단계는 없습니다. `--collect`로 정답이 붙은 기록을 남기고 `pinch_eval.py`로 "의도 → 실제 입력" 표를 만들어 판정값을 정합니다.
  ```bash
  python Project01/project01.py --camera 0 --collect      # 손마다 검지→소지 10바퀴 기록
  python Project01/project01.py --camera 0 --collect --collect-set edit   # 왼손 손등 키(모음·공백·확정·문장부호) 기록
  python Project01/project01.py --camera 0 --collect --collect-set right --save-video   # 오른손만 + 영상 저장
  python Project01/project01.py --camera 0 --collect --collect-set words --save-video   # 단어 32개를 이어서 치기
  python Project01/pinch_eval.py Project01/data/collect-*.jsonl -v  # 지금 판정으로 다시 돌려 표 출력
  ```
- 단어 기록(`--collect-set words`)은 단어를 하나씩 안내하고, 입력 칸이 그 단어가 되면 다음 단어로 넘어갑니다(틀리면 지우고 고쳐 칩니다. N 건너뜀, B 직전 다시). 단어 목록(`pinch_collect.WORDS`)에는 모든 자음 그룹, 모음 버튼의 세 가지(ㆍ·가로 ㅡ·세로 ㅣ), 복합 모음, 확정, 공백이 들어 있고, 단어마다 기대 단계를 입력기로 검증합니다(`word_steps`, 평가용 `word_keys`). `pinch_eval.py`는 단어 기록을 알아보고 기대 키 순서와 실제 꼬집기를 편집 거리로 맞춰 맞음·다른 손가락·더 들어감(오입력)·빠짐을 키별로 셉니다. 손가락 하나씩 쉬어 가며 안내하는 기록에는 손가락을 이어 옮길 때의 오입력(엄지가 검지를 지나감)이 나타나지 않아서 만들었습니다.
- `--save-video`는 로그와 같은 이름의 `.mp4`(열리지 않으면 `.avi`)에 HUD를 그리기 전 카메라 프레임을 저장하고, 로그 행마다 영상 안 프레임 번호(`frame`)를 남깁니다. landmark만으로 구분되지 않는 자세(가려진 중지 꼬집기)를 영상으로 다시 보거나, 전처리·학습 모델을 같은 영상으로 비교할 때 씁니다. 영상의 재생 속도는 30fps로 고정되어 실제 시간과 다를 수 있으니, 시각은 로그의 `t`를 기준으로 합니다.
- 손 방향은 손목·검지 뿌리·소지 뿌리가 이루는 2D 외적의 부호로 정하고, 새 방향이 0.15초 이어져야 바꿉니다(한 프레임 튐 무시). 그래서 손을 뒤집는 순간에는 이전 방향으로 판정됩니다. 꼬집기는 접촉의 처음 3프레임과 마지막 3프레임 손 방향 값의 중앙값이 모두 그 방향(손바닥 +0.25 이상, 손등 -0.25 이하)이어야 입력합니다(2026-10-23 기록의 뒤집기 오입력 5개 중 4개를 막음). 왼손·오른손은 MediaPipe 좌우 라벨을 따르고, 두 손에 같은 라벨이 붙었을 때만 화면 위치로 나눕니다(왼쪽 = 왼손). MediaPipe Tasks는 입력 영상에 보이는 실제 손을 라벨로 내므로, 영상을 좌우 반전했을 때만 라벨을 뒤집습니다(`common/hands.py`의 `true_label`).

## Vision Pro 앱 (`visionos/`)

같은 입력기를 Vision Pro에서 돌린다. ARKit 손 추적(실측 3D)을 MediaPipe 21점 형식으로 바꿔 넘기고, 판정은 앱에 넣은 Python 3.14(BeeWare Python-Apple-support)가 이 폴더의 `pinch_vision.py`·`pinch_typer.py`·`korean_ime.py`·`common/`을 그대로 실행한다. 준비·빌드·기기 설치는 [visionos/README.md](visionos/README.md).

## 환경 준비

아래 명령은 리포지토리 루트 `Vision-LLM-202035152` 기준입니다. 필요한 패키지는 OpenCV, NumPy, MediaPipe, Pillow입니다.

**Jetson**
- JetPack이 제공한 OpenCV/GStreamer 환경을 유지하고, 노트북의 MediaPipe 설치 안내를 따릅니다.
- Pillow가 없으면 `python -m pip install Pillow`로 추가합니다.
- USB 카메라는 `--pipeline usb`(practice의 `/dev/video0` 설정)로 엽니다. CSI 카메라는 `--pipeline 'nvarguscamerasrc ... ! appsink ...'`처럼 GStreamer 문자열 전체를 넘깁니다.

**macOS + iPhone 카메라**
- iPhone을 Continuity Camera로 씁니다. 이 환경의 OpenCV에는 GStreamer가 없으므로 `--pipeline` 대신 `--camera` 번호를 씁니다.
- OpenCV는 카메라를 `uniqueID` 문자열 순으로 번호를 매깁니다. 2026-10-18 기준으로 iPhone이 연결되어 있으면 0번이 iPhone, 1번이 내장 카메라입니다. iPhone 연결이 끊기면 0번이 내장 카메라가 됩니다.
- iPhone은 잠근 상태로 두고, 후면 카메라가 손을 향하게 합니다. iPhone을 움직이거나 잠금을 풀면 영상이 잠시 멈출 수 있습니다. 프로그램은 최대 10초 기다린 뒤 이어서 동작합니다.
- 처음 실행할 때 터미널 앱에 카메라 권한을 허용해야 합니다.
- iPad는 Mac 웹캠(Continuity Camera)으로 쓸 수 없습니다.
- MediaPipe는 수업 노트북처럼 `--no-deps`로 설치합니다. 의존성을 함께 설치하면 `opencv-contrib-python`이 따라 들어와 기존 OpenCV와 충돌합니다.

```bash
python -m pip install --no-deps mediapipe
python -m pip install absl-py flatbuffers sounddevice certifi
```

**폰트**
- 한글 폰트는 Noto CJK, 나눔고딕, 맑은 고딕, Apple SD Gothic Neo의 일반 설치 경로에서 찾습니다.
- 없으면 `--font /경로/한글폰트.ttf`를 지정합니다. Ubuntu의 Noto CJK 패키지는 `fonts-noto-cjk`입니다.

## 한글 조합 (`korean_ime.py`)

모든 입력기가 같은 조합기(`CheonjiinIME`)를 씁니다.
- 지원 범위: 현대 한글 모음 21개, 자음 순환, 초성·중성·종성 조합, 겹받침, 다음 모음으로 받침 이동
- 아래아 `ㆍ`와 `ㆍㆍ`는 모음 조합 중에 임시로 표시됩니다.
- 지움은 마지막 키 입력 한 번을 취소합니다. 예를 들어 `가`에서 한 번 지우면 `기`, 다시 지우면 `ㄱ`이 됩니다.

| 입력 | 결과 |
| --- | --- |
| ㄱ + ㅣ + ㆍ | 가 |
| ㅇ + ㅣ + ㆍ + ㄴ | 안 |
| ㄱ + ㆍ + ㅡ + ㅣ + ㆍ | 과 |
| ㅡ + ㆍ + ㆍ + ㅣ | ㅝ |

## 이전 시도

세 방식 모두 코드와 테스트가 남아 있고, 각각의 커밋에 경위가 적혀 있습니다.

| 방식 | 파일 | 결과 |
| --- | --- | --- |
| 엄지로 고른 키를 주먹으로 확정 (Jetson 원본) | 커밋 `767a19f`의 `project01.py` | 글자마다 손을 폈다 쥐어야 해서 입력이 거의 불가능했다. |
| 엄지로 마디를 누르면 입력, 주먹은 지움 | `project01.py`, `tap_*.py` | 단안 카메라로는 엄지가 마디에 닿았는지 판정하지 못해 iPhone 실기 시험에서 입력되지 않았다. |
| 자판 손 버튼을 선택 손으로 꼬집기 (방식 1) | `pinch_keyboard.py` | 입력은 되었지만(`ㅂㅂㅇㅈ`), 맞은편 카메라 배치에서는 사용자 시점과 화면이 달라 조작하기 어려웠다. |

**엄지 마디 누르기 (`project01.py`)**
- 키는 검지~소지 4개 손가락 × 끝·중간·뿌리 마디 3개, 모두 12곳의 중점에 놓입니다.
- 엄지 끝과 마디 선분 사이 거리를 MediaPipe world 좌표로 재고, 12mm 안이면 누른 것으로 봅니다(`--tap-enter`, `--tap-exit`, 실행 중 `[` `]`).
- 주먹은 지움입니다.
- `python Project01/project01.py --camera 0`으로 실행하고, `--demo`로 카메라 없이 `안녕하세요` 조합을 확인합니다.
- `tap_record.py`·`tap_eval.py`는 판정 방식을 비교하는 도구입니다. 안내에 따라 누르기·근접·띄우기·주먹 시행을 기록하고, 검출기별 정밀도·재현율·키 정확도·혼동 행렬을 냅니다. 카메라를 고정한 상태에서 기록해야 합니다. 세션은 `Project01/data/tap/`에 저장되며 git에 포함하지 않습니다.

**선택 손 꼬집기 (`pinch_keyboard.py`)**
- 왼손 손바닥을 자판으로 펴고, 오른손 엄지·검지 중점을 커서로 키 위에 둔 뒤 맞닿으면 입력합니다.
- 오므리기 시작할 때 강조된 키를 고정해 입력하고, 두 손이 겹치면 자판 손 위치를 1.5초까지 유지합니다.
- 왼손 주먹은 지움입니다.
- `python Project01/pinch_keyboard.py --camera 0`으로 실행합니다.
